# Clanka Operating System Website

The site at <https://www.clankos.org>.

The pages are Org files in `content/`. Emacs builds them into HTML in
`site/`, which is not kept in Git.

```sh
make build      # content/ -> site/
make serve      # build, then preview on http://localhost:8000
```

`make help` lists the rest. The build needs Emacs with Org and ImageMagick 7
(`magick`, with WebP support). `make serve` needs Python 3.

## Writing a page

Add an Org file under `content/`. `content/guide/start.org` becomes
`site/guide/start.html`. Give it a `#+TITLE`, which becomes the page's
heading, and a `#+DESCRIPTION`, which search engines show. Link to another
page as an Org file, `[[file:guide/start.org][Start]]`; the build writes the
link to the HTML page, and fails on a link to a file that is not there.

The header's menu and the footer's links are written out in `template.html`.
Add a new page's link to the menu there. The build marks the link to the page
being built with `aria-current="page"`.

Every other file under `content/` is copied as it is: the stylesheet, and any
image or font a page uses.

## Images from IPFS

Use an image link without a description, and give its alternative text in
Org's attributes:

```org
#+ATTR_HTML: :alt The gnubot at work in his forest workshop.
[[ipfs://bafybeibq2pwbwv2aakhpssihkcg3ejxver4agjhksismpcphpzn5ipxlf4/home.png]]
```

`image-lock.json` records the SHA-256 of the original bytes for each exact
IPFS address. Add or change the address and hash together from the verified
archive or publication manifest. An unlisted address fails the build.

`assets.el` fetches originals through an HTTP gateway and verifies their
hashes before caching them in `.cache/ipfs/`. ImageMagick creates WebP files
at quality 82, at most 1280 pixels wide, without upscaling. Their filenames
include a hash of the generated bytes. The export rewrites image links to
ordinary relative URLs under `site/img/`, including on nested pages. Org
source files stay unchanged; no images are committed in this repository.

```sh
# With the ClankOS initiation project's IPFS service running and images pinned:
make build IPFS_GATEWAY=http://127.0.0.1:18080

# Rebuild from verified cached originals, without contacting a gateway:
make build IPFS_OFFLINE=1

make test
```

The default gateway is `https://ipfs.io`; `IPFS_GATEWAY` selects another one.
The local node must be running for local downloads. A public gateway can
retrieve the images only while a reachable provider retains them. A local
pin is not a substitute for an always-available deployment provider.

`COS_ASSET_CACHE` selects a different cache directory. `make clean` removes
only the built site and retains this cache. Missing offline files, HTTP
errors, corrupt downloads and corrupt cached files stop the build. Remove
the named corrupt cache file to fetch it again. Original PNGs remain in
the archive and IPFS; generated WebP files are disposable build output.

The tests check exact HTTP body bytes, hash failures, offline cache use,
unsafe and unlisted links, nested-page paths, image attributes and derivative
reuse. The gateway and local Docker service are not needed for these tests.

## Changing how a page looks

`template.html` is the page around every Org file's body, and
`content/style.css` is the stylesheet. The template's placeholders are listed
in `publish.el`, which holds the build.

The site is served under a content security policy that allows no inline
script and no inline style, and nothing loaded from another site. Styling
goes in the stylesheet and fonts are served from `content/`. `make build`
fails if a page contains a `<script>`, a `<style>` or a `style` attribute.
